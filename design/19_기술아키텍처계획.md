# 19. 기술 아키텍처 계획 (Technical Architecture)

## 가정 (Assumption)
- 렌더링 엔진은 Three.js(WebGL2) 기반으로 확정(과제 전제 조건).
- 서버 사이드 스택(예: Node.js 백엔드, 특정 DB)은 본 문서 범위 밖으로 클라이언트 아키텍처 중심으로 기술한다.

## 1. Three.js 기반 렌더링 전략
| 항목 | 전략 |
|---|---|
| 렌더러 | WebGL2 우선, WebGL1 폴백(구형 기기 대응) |
| 셰이더 | 커스텀 ShaderMaterial 기반 2단 툰 셰이딩(03번 문서 라이팅 원칙 구현) + 림라이트 |
| LOD | 캐릭터 3단계(근/중/원), 지형 4단계 쿼드트리 기반 청크 LOD |
| 인스턴싱 | 식생/소품(풀, 바위 등) InstancedMesh로 드로우콜 최소화 |
| 그림자 | 모바일 '상' 옵션에서만 PCF 소프트섀도우 1개 디렉셔널 라이트, '중/하'는 베이크드 그림자맵으로 대체 |
| 후처리 | 최소 후처리(블룸만 선택적 적용), 모바일 GPU 부하 고려해 기본 비활성화 옵션 제공 |
| 씬 그래프 | 지역별(서브지역 5개) 독립 씬 청크로 분리, 경계 접근 시 비동기 프리로드 |

## 2. 모바일 성능 최적화 방침
| 항목 | 목표/방침 |
|---|---|
| 드로우콜 상한 | 필드 씬 기준 400콜 이하(모바일 중급 기기 30fps 유지 목표) |
| 폴리곤 예산 | 캐릭터 1인 8,000~12,000 트라이(만렙 스킨 기준), 필드 청크당 15만 트라이 이하 |
| 텍스처 규격 | 캐릭터 2048px 기본, 모바일 자동 다운스케일 1024px, 지형 타일 1024px 반복 텍스처 |
| 파티클 상한 | 03번 문서 기준(화면당 300개) 클라이언트 강제 컷오프 |
| 배터리/발열 대응 | 그래픽 옵션 '저사양 모드' 시 24fps 캡 + 후처리/그림자 완전 비활성화 |
| 메모리 관리 | 씬 전환 시 미사용 텍스처/지오메트리 명시적 dispose() 호출, 텍스처 아틀라스로 드로우콜/메모리 동시 절감 |

## 3. 세이브 / 에셋 로딩 구조
### 3.1 세이브 구조
- 서버 authoritative 저장(클라이언트는 캐시만 보유): 캐릭터/재화/진행도는 서버 DB 기준, 클라이언트 로컬스토리지는 UI 설정/그래픽 옵션 등 비게임플레이 데이터만 저장.
- 자동 저장 트리거: 퀘스트 완료, 가챠 결과, 육성 변경 등 상태 변경 즉시 서버 동기화(낙관적 UI + 실패 시 롤백).

### 3.2 에셋 로딩 구조
| 단계 | 전략 |
|---|---|
| 최초 진입 | 코어 번들(UI, 로비 씬, 캐릭터 셰이더)만 우선 로드 → 목표 8초 이내(04번 문서 로딩 목표) |
| 지역 진입 | 서브지역별 에셋 번들을 gzip/브로틀리 압축 + glTF(Draco 압축) 형식으로 스트리밍 |
| 캐릭터 에셋 | 보유 캐릭터만 로컬 캐시, 미보유 캐릭터는 가챠 연출 시점에만 온디맨드 로드 |
| CDN 전략 | 정적 에셋(모델/텍스처/오디오) 전량 CDN 서빙, 버전 해시 기반 캐시 무효화 |
| 점진적 품질 | 저사양 기기 감지 시 자동으로 텍스처/모델 저품질 번들로 전환(기기 벤치마크 최초 실행 시 1회 측정) |

## 4. 폴더 구조 설계 (클라이언트 기준 예시)
```
/src
  /core
    /engine          # Three.js 초기화, 렌더 루프, 입력 시스템
    /scene-manager   # 서브지역 씬 로드/언로드, 청크 스트리밍
    /save            # 서버 동기화, 로컬 캐시 레이어
  /gameplay
    /combat          # 콤보, 스킬, 공명 융합 반응 로직
    /movement        # 등반/활공/수영 컨트롤러
    /party           # 파티 편성, 스왑 로직
  /systems
    /gacha           # 공명 소환 로직, 확률 테이블
    /progression     # 레벨/돌파/성물 계산
    /economy         # 재화 트랜잭션
  /ui
    /screens         # 17번 문서의 화면별 컴포넌트
    /hud             # 조작 UI, 게이지
  /assets
    /characters
    /environments
      /armona-port
      /veluha-forest
      /karna-highlands
      /isna-ruins
      /falos-bay
    /audio
    /shaders
  /data
    /characters.json
    /fusion-reactions.json   # 06번 문서 공명 융합 표 데이터화
    /quests.json
/server (별도 리포지토리 가정, 본 문서 범위 밖 개요만)
  /api
  /db-schema
```

## 5. 확장성 고려 사항 (2.0 대비)
- 씬/에셋 구조를 "지역 = 독립 번들" 단위로 설계했기 때문에, `20_버전업데이트로드맵템플릿.md`의 신규 대륙 추가 시 기존 코드 변경 없이 `/assets/environments/` 하위에 새 폴더만 추가하는 방식으로 확장 가능하도록 설계 원칙을 고정한다.
